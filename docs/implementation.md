## Описание

Клиент серверное приложение. Клиент реализован как CLI. Сервер предоставляет REST API.

## Сервер

Сервер при запуске требует ввести мастер ключ.
Клиент получает объекты через REST API.
Сервер шифрует объекты и кладет в хранилище.
Файловые объекты сохраняются в S3.

### API

API сервера доступно только по протоколу TLS.

**Список эндпоинтов:**

- `POST /register` - регистрация пользователя
- `POST /login` - аутентификация пользователя

- `GET /list/items` - получить список объектов
- `GET /get/item` - получить объект
- `GET /get/file` - получить объект типа файл

- `POST /create/item` - создать объект
- `POST /create/file` - создать объект типа файл

- `DELETE /delete/item` - удалить объект

### Шифрование

Серверу при старте передается мастер ключ (MK).
При регистрации каждому клиенту создается уникальный клиентский ключ шифрования (КК) который шифруется с помощью МК и сохраняется в БД.
Сервер получает объект через API, извлекает и расшифровывает КК пользователя с помощью MK и шифрует данные объекта с помощью КК.

### Регистрация

Клиент отправляет в API логин и пароль.
Логин сохраняется с БД.
Пароль хешируется и сохраняется в БД.
Создается клиентский ключ шифрование, шифруется мастер ключом и кладется в БД.
Далее см. [Аутентификация](#аутентификация)

### Аутентификация

Клиент аутентифицируется с помощью логина и пароля.
Сервер сравнивает хеш пароля с сохраненным в БД.
Сервер выдает клиенту JWT токен.
Клиент сохраняет токен в файл ~/.gophkeeper/auth.json
В дальнейшем клиент аутентифицируется с помощью этого токена.
Когда у токена заканчивается время жизни сервер отдает соответствующую ошибку и клиент показывает пользователю сообщение, что нужно заново аутентифицироваться.

### Создание объекта

`POST /item/`

```json
{
  "type": "type",
  "title": "title",
  "data": "типоспецифичные поля объекта"
}
```

Сервер может принимать объекты разных типов, таких как:

- Login
- Note
- File
- Credit Card

Типы объектов:

```yml
Login:
  Title:
  Username:
  Password:
  URL:
  Notes:

Note:
  Title:
  Data:

File:
  Title:
  BinaryData:
  Notes:

CreditCard:
  Title:
  Number:
  Cardholder:
  CVV:
  ExpirationDate:
  Notes:
```

### Удаление объекта

`DELETE /delete/item?title=<title>`

Клиент отправляет запрос на удаление объекта по его названию.
Сервер проверяет, что объект принадлежит пользователю.
Сервер удаляет объект из БД.
Если объект типа файл, сервер также удаляет файл из S3 хранилища.

## Заметки из вебинара

Пользовательский сценарий работы с Gophkeeper

- Пользователь регистрируется
- Пользователь аутентифицируется
- Пользователь отправляет данные на сервер
- Сервер шифрует и сохраняет данные
- Пользователь подключается с другого устройства
- Пользователь получает список доступных данных
- Пользователь скачивает данные

Пользователь может получить список доступных данных (созданных этим пользователем) от сервера. Метаданные можно хранить "небезопасно".
