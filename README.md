# GophKeeper

GophKeeper — это клиент-серверная система, которая позволяет пользователям надёжно и безопасно хранить логины, пароли, бинарные данные и другую конфиденциальную информацию.

## Схема работы

### Шифрование

Для шифрования клиентских ключей, объектов и файлов используется AES-GCM
Объекты и файлы шифруются клиентскими ключами, nonce сохраняется в БД.

При шифровании файла он разделяется на чанки, в начало чанка записывается nonce фиксированного размера. Размер чанка и nonce префикс сохраняются в БД.

### Регистрация пользователя

Клиент отравляет на сервер логин и пароль, сервер шифрует пароль и сохраняет запись в БД. Сервер создает ключ шифрования пользователя и сохраняет в БД. Сервер отправляет клиенту токен (JWT) авторизации.

Клиент получает токен и сохраняет в файл. Далее клиент использует данный токен при запросах к серверу.

### Логин пользователя

Клиент отравляет на сервер логин и пароль. Сервер сравнивает хеш пароля с хешем в БД и отправляет пользователю токен в случае успеха.

### Создание объекта

Пользователь отправляет на сервер объект в виде

```json
{
    "title": "",
    "type": "",
    "data": {}
}
```

`data` это элемент зависящий от типа объекта.

Сервер получает объект, парсит `data` в зависимости от типа. Шифрует клиентским ключом и сохраняет в БД

В случае создания объекта типа файл клиент дополнительно отправляет файл, который шифруется на стороне сервера и сохраняется в хранилище S3.

### Получение объекта

Клиент запрашивает объект по названию. Сервер расшифровывает клиентский ключ, расшифровывает объект и отдает клиенту.

В случае если объект типа файл сервер дополнительно отдает клиенту файл.

При запросе файла клиент указывает куда его сохранить.

### Удаление объекта

Клиент отправляет запрос на удаление объекта по его названию. Сервер проверяет, что объект принадлежит пользователю, и удаляет его из БД.

В случае если объект типа файл, сервер дополнительно удаляет файл из хранилища S3.

## Сервер

Сервер и инфраструктурные компоненты можно запустить с помощью ./docker-compose.yml файла в корне проекта.

Серверу необходимы следующие инфраструктурные компоненты:

* postgresql
* s3 совместимое хранилище

Сервер принимает следующие параметры запуска:

* `GK_DEBUG` - включить отдалочные логи
* `GK_ADDRESS` - адрес на котором запустить сервер
* `GK_DATABASE_URI` - dns postgresql сервера
* `GK_S3_ENDPOINT` - адрес хранилища s3
* `GK_S3_ACCESS_KEY` - access key id хранилища s3
* `GK_S3_SECRET_KEY` -  access key хранилища s3
* `GK_S3_BUCKET_NAME` - имя бакета хранилища s3
* `GK_TLS_CERT_FILE` - имя файла сертификата tls
* `GK_TLS_KEY_FILE` - имя файла приватного ключа tls
* `GK_JWT_SECRET` - ключ для jwt токенов
* `GK_MASTER_KEY` - мастер ключ для серверного шифрования

Параметры могут передаваться как через переменные окружения, так и через параметры командной строки. Также можно использовать конфиг файл.

### Команда запуска сервера

**Запуск сервера**
`run`

**Показать версию**
`version`

## Клиент

Клиенту для работы необходимы следующие параметры:

* `--server-url` - адрес сервера
* `--config-file` - имя конфигурационного файла

Опционально:

* `--auth-config` - имя файла для хранение аутентификационных данных
* `--debug=true` - для включения отладочных логов

Все параметры могут передаваться как в командной строке, так и через конфигурационный файл.

### Команды клиента

**Зарегистрировать пользователя:**
`register [email] [password]`

**Залогинить пользователя:**
`login [email] [password]`

**Создать объект на сервере**
`create item <type_name> --title name [type_specific_flags]`

**Получить объект с сервера**
`get item --title name [--file-path path]`

**Вывести список объектов**
`list items [--type type]`

**Удалить объект с сервера**
`delete item --title name`

**Показать версию**
`version`


## Метрики

Во время работы сервера собираются метрики. Для сборки Prometheus они доступны на `/metrics` эндпоинте.

Кастомные метрики:

* `total_http_requests` - кол-во http обращений к серверу.
